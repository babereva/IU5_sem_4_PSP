## Цель работы

Знакомство с разработкой **backend-приложений** на платформе **Node.js** с использованием фреймворка **Express.js**, а также с принципами построения **REST API**: маршрутизацией, контроллерами, сервисным слоем и обработкой HTTP-методов.


## Задание

Разработать REST API для управления списком продуктов: реализовать CRUD-операции (создание, чтение, обновление, удаление), фильтрацию по параметрам запроса, хранение данных в JSON-файле, а также middleware для логирования запросов и глобальной обработки ошибок. Код организовать по слоям: маршруты → контроллеры → сервисы.


## Структура проекта

```
src/
├── index.js                    # Точка входа, настройка Express
├── routes/
│   └── products.js             # Маршруты /products
├── controllers/
│   └── productsController.js   # Обработка запросов
├── services/
│   ├── productsService.js      # Бизнес-логика
│   └── fileService.js          # Чтение/запись JSON-файла
└── data/
    └── products.json           # Хранилище данных
```

Сервер запускается на `http://localhost:3000`. Доступные эндпоинты:

| Метод    | Маршрут         | Описание                              |
|----------|-----------------|---------------------------------------|
| GET      | `/products`     | Получить все продукты (с фильтрацией) |
| GET      | `/products/:id` | Получить продукт по ID                |
| POST     | `/products`     | Создать новый продукт                 |
| PATCH    | `/products/:id` | Обновить продукт частично             |
| DELETE   | `/products/:id` | Удалить продукт                       |
| OPTIONS  | `/products`     | Получить список допустимых методов    |
| OPTIONS  | `/products/:id` | Получить список допустимых методов    |


## Дополнительное задание на защите

На защите было предложено реализовать поддержку метода **OPTIONS** для маршрутов `/products` и `/products/:id`. Метод OPTIONS используется для предварительных CORS-запросов и позволяет клиенту узнать, какие HTTP-методы доступны на данном эндпоинте.

**Реализация** — файл `src/routes/products.js`.

Для обоих маршрутов добавлены отдельные обработчики `router.options(...)`, которые устанавливают заголовок с перечнем допустимых методов и возвращают статус `204 No Content`:

```js
router.options('/', (req, res) => {
    res.set('GET', 'POST', 'PATCH', 'DELETE', 'OPTIONS');
    res.status(204).send();
});

router.options('/:id', (req, res) => {
    res.set('GET', 'POST', 'PATCH', 'DELETE', 'OPTIONS');
    res.status(204).send();
});
```

Маршруты подключаются в `src/index.js`:

```js
app.use('/products', productsRouter);
```

Логирующий middleware фиксирует все входящие запросы, включая OPTIONS:

```js
app.use((req, res, next) => {
    console.log(`[${new Date().toISOString()}] ${req.method} ${req.url}`);
    next();
});
```
